# Setup

This repository is the source for the GitHub profile of **Al Shahriar Sowan**
([@Alshahriar-07](https://github.com/Alshahriar-07)). The README is assembled from
standalone SVG cards generated by Python from one content file and a real
contribution feed. There are no third-party card services, no JavaScript, and no
runtime dependencies in the rendered images.

## What is in here

```
README.md                     the profile page, assembled from cards
generate_cards.py             renders every SVG card
cards/                        generated: hero, three profile tiles, section rails, activity, ...
cards/projects/               generated: flagship SeedCode CLI showcase + five product cards
data/contributions.json       real contribution data, refreshed daily
scripts/content.py            all personal copy, links, products, roles, education
scripts/svg_kit.py            palette, fonts, motion, text measurement, SVG wrapper
scripts/fetch_contributions.py GraphQL first, public calendar fallback
scripts/make_ascii_svg.py     renders the 180x96 character portrait from me.png
scripts/prep_portrait.py      crops/compresses the source photo (optional WebP asset)
scripts/validate_output.py    XML, safety, glyph, README and mode validation
fonts/                        licensed subset WOFF files, embedded per card
assets/me.png                 original portrait (never modified)
assets/me_ascii.svg           transparent character portrait (hero rows + standalone)
assets/portrait.webp          generated 4:5 photo (kept as a source asset)
.github/workflows/refresh-profile.yml daily + manual refresh
```

`Reference Repo/`, `old repo of mine/`, the resume PDF and `.venv/` are excluded
by `.gitignore`; they are workspace inputs, not part of the published profile.

## Local preview

Requires Python 3.10+.

```bash
python -m venv .venv
# Windows (Git Bash): source .venv/Scripts/activate
# macOS / Linux:      source .venv/bin/activate
pip install -r requirements.txt

python scripts/fetch_contributions.py     # writes data/contributions.json
python generate_cards.py                  # animated cards/ + validation
```

Open `README.md` in a GitHub-flavoured Markdown preview, or open any file in
`cards/` in a browser. GitHub serves README images through its own image proxy,
so the cards are also safe in the GitHub web UI.

### Static build

For email, print, or any environment where motion is unwanted:

```bash
STATIC=1 python generate_cards.py --out build/static
```

The static output has no `@keyframes`, no `<animate>` and no `<set>` elements.
The normal output still respects `prefers-reduced-motion`.

### Render a labelled test fixture

If the network is unavailable, or you want to test the layout without touching
real data:

```bash
python scripts/fetch_contributions.py --sample data/sample-contributions.json
python generate_cards.py --out build/sample --data data/sample-contributions.json
```

The fixture is marked `"sample": true`, its cards visibly say **SAMPLE DATA -
NOT REAL**, and the generator refuses to write a sample into `cards/`. Never
commit a fixture as `data/contributions.json`.

## Publishing

1. Create a **public** repository named exactly `Alshahriar-07` on the
   `Alshahriar-07` account. GitHub shows a repository with that name on your
   profile.
2. Push this project to it:

   ```bash
   git init
   git add .
   git commit -m "feat: build profile cards"
   git branch -M main
   git remote add origin https://github.com/Alshahriar-07/Alshahriar-07.git
   git push -u origin main
   ```

3. In **Settings → Actions → General**, make sure workflows have read and write
   permission for repository contents (the workflow requests `contents: write`
   itself).
4. Run **Actions → Refresh profile cards → Run workflow** once to confirm the
   pipeline. It runs daily at 04:23 UTC (10:23 in Dhaka).

If you are publishing from your existing local clone (`old repo of mine/`), copy
the tracked files into that clone and keep its `.git`, or push this directory as
shown above. The old README and workflows are intentionally preserved in the
workspace for comparison, not published.

## Contribution data

`scripts/fetch_contributions.py` tries, in order:

1. **GitHub GraphQL** using `GITHUB_TOKEN` (the Actions token by default).
2. **GitHub's public contribution calendar** HTML, with retries for rate limits.
3. **No write**: if both fail, the previous `data/contributions.json` is kept and
   the command exits successfully. A failed fetch never produces zeroed stats.

The JSON records its `source` (`github-graphql` or `github-html`) and a
`generated_at` UTC timestamp. The cards display only values derived from the
daily counts: totals, active days, streaks, best day, monthly bars, and the
current month.

### Private contributions

The default `GITHUB_TOKEN` can see public contributions. To include private
contributions in the total, create a classic personal access token with
`read:user`, add it as a repository secret named `PROFILE_TOKEN`, and change the
workflow env to:

```yaml
GITHUB_TOKEN: ${{ secrets.PROFILE_TOKEN }}
```

Only do this if you are comfortable with a long-lived token; the default token
is safer and works for this profile.

## Customization

- Copy, links, projects, skills, experience and education live in
  `scripts/content.py`. Edit that file, then run `python generate_cards.py`.
- Do not hand-edit files in `cards/`; they are overwritten.
- The hero portrait is a 180x96 character grid generated from `assets/me.png`
  by `scripts/make_ascii_svg.py` into `assets/me_ascii.svg`. The hero and the
  standalone transparent asset use the same rows. Replace the photo and delete
  `assets/me_ascii.svg`, then regenerate. The original is never modified.
  `scripts/prep_portrait.py` still produces the 4:5 `assets/portrait.webp`.
- The three profile tiles are defined in `TILES` in `scripts/content.py`; the
  README row shows them at 32.5% width.
- Colors, type and motion live in `scripts/svg_kit.py`.
- The README only needs to change if you add or rename a card.

## Validation

```bash
python scripts/fetch_contributions.py --check
python generate_cards.py
python scripts/validate_output.py --dir cards --data data/contributions.json --readme README.md
STATIC=1 python generate_cards.py --out build/static
python scripts/validate_output.py --dir build/static --data data/contributions.json --static
```

`generate_cards.py` runs the validator automatically. It checks that every SVG
parses, contains no scripts or external resources, embeds its fonts, and contains
no missing glyphs; that every image referenced by the README exists; that the
contribution totals agree with the daily data; and that static/animates modes are
actually static/animated.

## Troubleshooting

- **GraphQL 401/403**: the token is missing or lacks profile access. The script
  falls back to the public calendar automatically.
- **Only public numbers**: private contributions are not included unless you use
  a token that can see them (see above).
- **Images look stale on GitHub**: GitHub's image proxy caches aggressively.
  Wait a few minutes, then hard-refresh. The commit is what updates the source.
- **A schedule did not run**: scheduled workflows are disabled after 60 days of
  repository inactivity. Re-enable the workflow or run it manually.
- **Fonts render as system fonts**: the WOFF data must remain embedded. Do not
  externalize the `@font-face` URLs; GitHub's image proxy only permits `data:`
  resources inside SVG.
- **No commit after a run**: if the new data is identical, the workflow leaves the
  repository untouched by design.

## Design and licensing

The palette is charcoal, bone-white and one muted sand accent. Display type is
Instrument Serif, UI type is Geist, and technical labels are Geist Mono, all under
the SIL Open Font License 1.1 (see `fonts/README.md`). The cards are hand-built
SVG with CSS keyframes and SMIL count-ups; no chart library, icon pack or stock
image is used.
